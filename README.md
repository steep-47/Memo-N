# Memo-N

Memo-N 是一个独立的 SillyTavern 动态世界记忆插件。它在一次正常聊天请求中同时生成完整正文与结构化记忆变化，再由本地严格事务执行器更新七张世界状态表。

## 七张世界记忆表

1. 当前状态
2. 角色状态
3. 背包
4. 当前任务与约定
5. 人物主表
6. 人物发展表
7. 历史事件

人物主表保存稳定身份信息，人物发展表保存最后确认的发展锚点。预设人物可选择完整记录、只记录剧情变化或不记录，并支持人物置顶。

## 伊依独立长期记忆

Memo-N 另有一套与七张世界表完全分离的“伊依长期记忆库”。它负责记忆工程，不负责定义伊依的人格、文风、口癖或具体剧情表现；这些仍由当前预设和正常上下文决定。

- 存储在独立全局用户设置中，不写入当前聊天七表。
- 新游戏、换聊天或清空世界表不会自动清空伊依长期记忆。
- 每轮使用独立召回引擎按当前话题相关性、重要度和重复召回冷却选择少量记忆，而不是全量注入。
- 当前召回默认最多 10 条，并受约 650 字符的软限制；限制只影响发送给模型的记忆，不删除底层长期记忆。
- 召回分为“当前相关”和“背景锚点”；被召回只表示可供模型参考，不代表正文必须主动提起。
- 普通闲聊和一次性动作不形成长期记忆；短暂情绪属于当前状态，不等同于永久记忆。
- 情绪保存当前状态、原因、0–3 强度、增强/稳定/缓和走势和情绪余波。
- 关系不是好感度或固定等级。除自然语言关系概括外，还保存基于真实经历形成的现实预期、信任依据、相处方式、主动边界以及舒适/谨慎区域。
- 关系字段保存“当前有效理解”；只有足够的新证据才更新，不建立固定升级路线。
- 冲突与纠正优先更新已召回的原记忆：旧事实本身错误时直接修正原条目；旧事件真实但后续理解改变时保留事件，只更新“现在怎么看”，避免互相矛盾的条目同时堆积。
- 自动维护只做可证明安全的精确去重：同一时间/阶段且记忆正文完全一致的重复项会合并，并保留更高重要度与更完整的后续信息。
- 容量管理采用“限制召回、不按年龄或数量删库”的原则。达到大量记忆时只降低每轮注入量并给出维护信号；不会因为记忆旧或条目多就自动删除长期记忆。
- 自动写回复用正文同一次模型请求，不额外增加 API 调用；没有长期变化时不写新记忆。
- Swipe、Regenerate、删除 Swipe、删除消息和编辑消息都有独立事务回滚，避免不存在的分支留下“幽灵记忆”。
- 伊依事务使用逐字段 CAS 回滚，尽量避免旧聊天回滚覆盖其他聊天后来形成的新记忆。
- 独立记录 API、表格整理等记录专用请求不会触发伊依记忆写回。
- 设置页可手工查看、修改、添加、删除、导入、导出或清空伊依记忆，也可直接查看和调整关系结构、当前情绪强度、走势与余波。

## 主要特性

- 正常模式只调用一次 API，不会因记录失败自动补发。
- CUSTOM OpenAI 兼容端点使用 JSON Schema 结构化响应；DeepSeek 直连与其他 relay 保留各自稳定协议。
- 表格变更只接受固定的 insert、update、delete 对象。
- 一轮变更全部成功才保存，任一步失败都会完整回滚。
- 表格失败不删除正常正文，也不会猜测修复非法操作。
- 每个聊天和 Swipe 使用各自的世界表格快照。
- 保留表格编辑、导入导出、整理、排序、行移动和表格目录移动等功能。
- 设置、API 私密数据、模板、聊天表格与 Swipe 数据均使用 Memo-N 独立存储键。

## 安装

插件目录必须命名为：

```text
SillyTavern/public/scripts/extensions/third-party/Memo-N
```

Memo-N 不是原 Memo 的覆盖升级包。安装 Memo-N 不会读取、迁移、删除或覆盖原 Memo 数据。

如果原 Memo 仍然安装，建议在 SillyTavern 扩展管理中只启用其中一个记录插件，避免两套插件同时向同一次模型请求注入各自的记录协议。即使同时存在，两者的持久化数据也彼此独立。

## 安全原则

- 不自动重试，不产生失败后的额外 API 费用。
- 不把 SQL 或其他非法文本转换成表格操作。
- 空表只能插入；更新和删除必须引用真实存在的行。
- 保存失败、快照失败和切换聊天都会停止写入或回滚。
- 数字 `0` 会按原值保存。
- 伊依后台记忆不能改变剧情世界事实、NPC认知、人物好感、背包、能力或历史事件。
- 伊依长期记忆不会因为年代久远或数量增加而自动删除；只有明确人工删除或可证明安全的精确重复合并会减少条目。
