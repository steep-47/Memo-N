# Memo-N

Memo-N 是一个独立的 SillyTavern 动态世界记忆插件。默认在一次聊天请求中生成完整正文与原生 `<tableEdit>` 记忆记录，再由本地事务执行器更新世界状态表。

当前版本：`0.79`。版本以 `manifest.json` 为准；加载器和本文保持一致。模块 URL 中的 `?v=` 是缓存标识，不是插件发布版本。

## 七张世界记忆表

| 表号 | 表名 | 主要用途 |
| --- | --- | --- |
| 0 | 当前状态 | 当前日期、时间、地点及场景人物 |
| 1 | 角色状态 | 玩家本人的身份、能力、外貌与当前状态 |
| 2 | 背包 | 玩家实际持有的物品与数量 |
| 3 | 当前任务与约定 | 当前仍有效的任务、承诺、约定及有期限持续事项 |
| 4 | 人物主表 | NPC 稳定身份、长期属性与重要信息 |
| 5 | 人物发展表 | NPC 最后确认的发展状态、地点与目标 |
| 6 | 历史事件 | 高召回记录已发生的连续性事实，后续由冗余整理压缩为完整事件 |

人物主表与人物发展表通过同一 NPC 姓名关联。预设人物支持记录策略选择与置顶。未知信息不应由模型猜测补齐。

## 记录与整理

- **正常聊天**：默认使用单次 API。保持预设的正文、状态栏和选项格式，在正文后附带唯一记录块；若预设要求单个 XML 根节点，记录块放在根节点内部末尾，不放入思考区或代码围栏。
- **正文保留**：移除正式记录块时保留正文空白和 XML 结构，Continue 续写保留新旧段落间的分隔。
- **本轮识别**：正式记录块携带本轮 `memo-round` 标识。记录引擎根据当前真实表头、行号和对象映射提供操作协议。
- **对象核对**：背包、人物主表和人物发展表的更新与删除需提供修改前的对象名，避免行号变化后误改对象。
- **表6高召回记录**：每个有实际剧情推进的回复都记录本轮已发生且对后续连续性有价值的事实；记录阶段不跨轮压缩、覆盖或删除旧事件链。
- **手动更新表格**：记录待处理剧情，不替代全局正确性维护。
- **表格整理**：负责七表正确性维护，包括重复实体/物品/任务、失效或到期事项、错位、字段混写和旧值冲突；结束事项先结算明确结果再删除。
- **冗余整理**：压缩内容冗余与表6逐轮事件记录；请求只读取表名、表头和数据行，不携带记录阶段的 sourceData/editRules，避免“记录时不得跨轮压缩”与“整理时应合并事件”互相冲突。已形成完整且无明显冗余的历史事件视为稳定单元，重复执行时不应继续缩短；明确终局作为事件边界，未闭合事件可在后续整理时继续合并。
- **旧聊天规则迁移**：打开或切换已有聊天时，标准七表只同步当前版本的规则元数据（note/init/insert/update/delete/description）；不会因此重建表格、修改表头或改写任何数据行。
- **独立记录 API**：默认关闭；开启后在正文之外额外调用记录 API，记录语义和执行协议与单次 API 相同。

手动更新和整理通过“格式锁注入 → API → 严格执行器”处理。非法操作、未知字段和无法识别的残留内容会被拒绝。

当前主加载链不启用仓库中保留的旧 DeepSeek JSON/工具调用桥，也不再要求助手以前缀 `<tableEdit><!--` 开始回复。正常记录引擎保留预设/API 的结构化输出设置；具体模型是否遵守记录协议仍需实际验证。

## 历史冻结

默认开启，保留最近 **50 个真实对话轮**；一轮按一个用户消息及其后的 AI 回复计算，可在设置中调整保留轮数或关闭。

更早的聊天只从发给 API 的历史副本中移除：**不总结、不生成归档块、不发送旧 recap、不删除酒馆聊天原文**。长期信息由世界状态表承接。这已替代旧版“50＋25 固定分块归档”的行为。

实现按角色与规范化后的完整文本匹配真实聊天消息；系统注入和世界书等不属于移除对象。无法匹配的消息会保留，因此其他扩展改写提示词后，实际发送量可能超过设置轮数。

## 数据与执行边界

- 每个聊天和 Swipe 保存各自的表格快照；支持编辑、导入导出、排序、行移动和目录移动。
- 设置、API 私密配置、模板、聊天表格与 Swipe 数据使用 Memo-N 独立存储键。
- 批次全部成功才保存；执行或保存失败时尝试完整回滚，正常正文保留。
- 不自动重试，不因失败额外调用 API；数字 `0` 按原值保留。
- 行号和列号以当前真实表格为准。空表删除视为无变化；非空表越界删除和普通越界更新会被拒绝。
- 执行器保留一个受限兼容行为：对空的背包/人物主表/人物发展表，若更新第 0 行同时提供有效数据、非空名称且与核对名一致，可转换为首次插入；其他空表更新仍拒绝。模型协议仍要求新增使用 `insertRow`。

## 安装

插件目录必须命名为：

```text
SillyTavern/public/scripts/extensions/third-party/Memo-N
```

Memo-N 不是原 Memo 的覆盖升级包，不会读取、迁移、删除或覆盖原 Memo 数据。若同时安装两者，建议只启用一个记录插件，避免向同一次请求注入两套记录协议。

## 开发与维护

- `manifest.json`：扩展清单与发布版本。
- `loader.js`：加载主入口，再按顺序加载运行时模块。
- `index.js`、`core/`：宿主事件、表格模型与管理入口。
- `scripts/engine/`：单次 API 记录协议与回复解析。
- `scripts/runtime/`：事务执行、快照、历史冻结、结构维护与兼容逻辑。
- `scripts/editor/`、`scripts/renderer/`、`scripts/ui/`：编辑与显示。
- `tests/`：Node.js 测试脚本，多数使用宿主模拟对象，不替代酒馆实测。

`index.js` 与 `core/manager.js` 有循环引用，加载器必须使用标准 `./index.js` URL，不能单独给入口添加缓存查询参数，否则浏览器可能创建两个入口实例。传输守卫先安装、输出格式锁后安装的顺序也必须保留。

在仓库根目录执行全部测试（需要支持现有脚本语法的现代 Node.js）：

```sh
status=0
for test in tests/*.mjs; do
    node "$test" || status=1
done
exit "$status"
```

维护检查的通过情况与尚未解决的问题见 [维护记录](docs/maintenance.md)。
