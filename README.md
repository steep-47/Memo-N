# Memo-N

Memo-N 是一个独立的 SillyTavern 动态世界记忆插件。正常模式在一次聊天请求中生成原生 `<tableEdit>` 记忆变化与完整正文，再由本地严格事务执行器更新七张世界状态表。

## 七张世界记忆表

1. 当前状态
2. 角色状态
3. 背包
4. 当前任务与约定
5. 人物主表
6. 人物发展表
7. 历史事件

人物主表保存稳定身份信息，人物发展表保存最后确认的发展锚点。预设人物可选择完整记录、只记录剧情变化或不记录，并支持人物置顶。

## 主要特性

- 默认使用单次 API 模式：同一次回复先生成一个原生 `<tableEdit>` 记录块，再继续输出正常正文、状态栏和行动选项。
- 记录块虽然置于实际输出首段，但以内部已经确定的完整正文和玩家下次输入前的最终落点为准；多段时间/地点推进不再照抄开头状态栏。
- “手动更新表格”以记录当前待处理剧情为第一目标，同时允许修复与本轮涉及对象直接相关、且证据明确的重复、错位、漏记或失效记录；不借此全局清理无关旧数据。
- “表格整理”以七表整体最终状态的全局整理为第一目标，同时负责修理重复、过期、错表、字段混写、旧值冲突以及最近聊天能够直接证明的明确漏项。
- 手动更新和表格整理的独立 API 返回都经过本地 tableEdit 传输守卫：完整记录块直接使用；只漏掉外层 `<tableEdit>` 时仅补传输外壳；若模型把 `insertRow/updateRow` 的 data 对象写成明确且可安全解析的 XML 属性形式，会先规范化为标准调用，再交给同一严格执行器检查。截断、重复块、未知属性、非法 data、非法操作或夹杂无法识别内容仍拒绝，不自动重试。
- 0.22 额外兼容 DeepSeek 偶发返回的结构化 XML 操作：`<tableIndex>N</tableIndex><operation><action>insert/update/delete</action>...`，其中 data 只能由唯一的 `<colN>纯文本</colN>` 组成；update/delete 必须给出合法 rowIndex。兼容层只负责转换为标准 insertRow/updateRow/deleteRow，再由原严格执行器检查真实表、行、列和事务边界；未知标签、重复列、非法索引或嵌套 XML 仍整批拒绝。
- 0.23 为手动更新和表格整理增加唯一输出格式锁：请求发出前强制注入统一 tableEdit 函数协议，输入里的 XML 标签只作为资料分隔符；返回兼容层继续作为兜底，执行链固定为“格式锁注入 → API → 兼容规范化 → 严格执行器”。
- 0.24 将字段维护规则改为方法式判断而不是按个案追加禁令：先判断事实性质和唯一主位置；外貌按“可观察性→持续性→辨识度→信息压缩”抽取当前视觉事实，一段叙述包含多类信息时拆分归类，不整句搬运。
- 钱财戳只对应玩家实际持有的钱、金银铜钱、通用灵石等货币余额，并写入玩家状态表的钱财/灵石字段；可出售或贵重的普通物品仍只写背包，不会因为有价格而被当作钱财。
- 灵力、神识、体力、伤势、增益与异常等属于当前状态戳，并写入玩家状态表的对应状态字段；字段曾漏记但当前上下文仍可确认时允许补齐，数字 `0` 不会被当成空值。
- 角色状态表保存玩家本人完整资料：除原有状态、能力与“外貌特征”外，0.20 新增“身份/所属”和“别名/称号”。底层保留既有15列原索引，新字段追加在末尾；旧聊天按表头映射补列，不会使原有数据错位。手机数据页只在展示层按信息密度重排为两段：人物/基础资料与能力/当前状态，真实底层列号不变，拆分视图仍复用原 Cell 的编辑、历史和列操作菜单。
- 0.21 为数据页增加视图稳定守卫：表格刷新按完成边界串行，旧异步渲染出现并发时会按真实 Sheet UID 去除重复视图；热更新检测到已有 Memo-N 主入口时不再重复启动 `index.js`，并自动清理同 ID 的重复表格抽屉。该修复只作用于前端视图，不复制、合并或删除真实七表数据。
- “技能/术法”与“擅长”按信息层级区分：前者记录明确掌握、可作为具体技法独立训练或施展的技能；后者记录长期稳定的能力领域、熟练事项和优势。身份、称号、外貌、能力、状态等各有主位置，整理时可修复明确错栏与重复内容。
- 普通装备、工具、文书、材料、丹药、符箓和生活物资只维护在背包表。交易时货币余额与物品库存分别更新，同一对象不会跨表重复记录。
- 导入旧聊天时，剧情历史和旧 `tableEdit` 只用于补回事实，不能证明当前表格仍有对应行。每轮协议会列出七表当前真实行数；`rowIndex` 只服从当前表格第一列，避免按历史插入顺序猜行号。
- 对空表执行删除会按“目标已经不存在”安全视为无变化，不再拖累同批其他合法记录；非空表越界删除及所有越界更新仍会整批拒绝，继续防止改错人物或物品。
- 使用 SillyTavern 内置直连 DeepSeek 且未启用工具调用时，利用 DeepSeek 原生助手前缀续写把同一次回复硬性固定为从 `<tableEdit><!--` 开始；接口只返回续文时，插件会在本地补回已知前缀后再解析，不会增加 API 调用。
- 不再把整段正文包装为 JSON，也不再使用自定义 `MEMO_N_CHANGES` 标记，减少思考模型在多轮对话中的截断与格式漂移。
- 下一轮请求会在发出的历史副本中恢复上一轮已执行的记录块，让模型持续看到一致的输出范例；聊天正文仍保持干净。
- “独立记录 API”默认关闭；只有手动开启时，才会在正文后额外调用一次记录 API。
- 表格变更只接受固定的 insert、update、delete 对象；data 键支持数字列索引或当前表中完全一致的真实表头名。整理模型偶尔省略 `updateRow` 的 `rowIndex` 时，仅在目标表恰好一行的情况下安全对应第 0 行。
- 一轮变更全部成功才保存，任一步失败都会完整回滚。
- 表格失败不删除正常正文，也不会猜测修复非法操作。
- 每个聊天和 Swipe 使用各自的世界表格快照。
- 保留表格编辑、导入导出、整理、排序、行移动和表格目录移动等功能。
- 设置、API 私密数据、模板、聊天表格与 Swipe 数据均使用 Memo-N 独立存储键。

## 安装

插件目录必须命名为：

```text
SillyTavern/public/scripts/extensions/third-party/Memo-N
```

Memo-N 不是原 Memo 的覆盖升级包。安装 Memo-N 不会读取、迁移、删除或覆盖原 Memo 数据。

如果原 Memo 仍然安装，建议在 SillyTavern 扩展管理中只启用其中一个记录插件，避免两套插件同时向同一次模型请求注入各自的记录协议。即使同时存在，两者的持久化数据也彼此独立。

## 安全原则

- 不自动重试，不产生失败后的额外 API 费用。
- 不把 SQL 或其他非法文本转换成表格操作。
- 空表只能插入；更新和删除必须引用真实存在的行。
- 保存失败、快照失败和切换聊天都会停止写入或回滚。
- 数字 `0` 会按原值保存。
当前版本：`0.24`。
