# Memo-N

Memo-N 是一个独立的 SillyTavern 动态世界记忆插件。它在正常聊天中生成正文与结构化记忆变化，再由本地严格事务执行器更新七张世界状态表。

## 七张世界记忆表

1. 当前状态
2. 角色状态
3. 背包
4. 当前任务与约定
5. 人物主表
6. 人物发展表
7. 历史事件

人物主表保存稳定身份信息，人物发展表保存最后确认的发展锚点。

## 记录接口与协议

Memo-N 设置中的「记录接口」是 DeepSeek / 中转站的唯一人工路由选择。插件不会根据 URL、模型名、`chat_completion_source`、`custom`、`reverse_proxy` 等字段自动猜测接口。

同一个手动选择同时决定“实际使用哪个 API”和“该记录入口使用什么机器协议”：

| 记录入口 | DeepSeek | 中转站 |
| --- | --- | --- |
| 普通一次 API | JSON `reply + changes` | 前置 `<tableEdit>` + 完整正文 |
| 独立记录 API | 主 API，记录专用 JSON `reply:"RECORD_ONLY" + changes` | 自定义 API，唯一 `<tableEdit>` |
| 手动「立即填表」 | 与独立记录相同的 DeepSeek JSON | 与独立记录相同的中转 `<tableEdit>` |

设置里的「填表行为发生在」是唯一模式选择：

- `聊天的同时填表`：普通一次 API，同一次模型请求同时完成正文与记录。
- `收到消息后再单独填表`：正文完成后额外调用一次记录 API。

不再额外显示第二个“独立记录 API”开关，也不再显示旧的“使用主API”路由勾选框；独立记录到底走主 API 还是自定义 API，完全由「记录接口」决定。中转站独立记录仍保留自定义 API URL / Key / 模型配置。

普通一次 API 选择中转站时，为避免长正文写到末尾时机器块被截断，模型必须先输出一个完整 `<tableEdit>`，闭合后再继续完整正常正文；Memo-N 本地解析后会从用户可见正文中剥离机器块。

独立/手动记录选择 DeepSeek 时不要求剧情正文，`reply` 固定为 `RECORD_ONLY`，真正的表格变化只放在 `changes`。选择中转站时仍使用原插件适合纯记录任务的唯一 `<tableEdit>`。

memon70–72 曾用于普通中转一次 API 的 `MEMO_N_CHANGES_V1 ... MEMO_N_CHANGES_END` tagged JSON 仅保留旧回复兼容解析，不再用于任何新请求。

直接编辑表格/单元格不调用模型 API，不受记录接口选择影响。

DeepSeek 的 `changes` 与中转站的 `<tableEdit>` 最终都会进入同一个严格事务执行器。记录失败不会自动补发第二次请求，也不会根据正文猜测应写入的表格变化。

## 中转站一次 API 的输出顺序

普通一次 API 选择中转站时，Memo-N 会在七表提示、最终 system 消息和最后一条 user 消息三处同步强化同一约束：

```text
<tableEdit><!--
updateRow(0,0,{1:"08:30"})
--></tableEdit>
这里开始完整正常正文……
```

没有表格变化时仍先输出：

```text
<tableEdit><!-- NO_CHANGE --></tableEdit>
```

解析器同时兼容机器块偶尔出现在正文尾部或正文中间，也会检查当前 Swipe 的 reasoning 区；但新请求明确要求前置机器块，以降低长回复末尾截断造成的记录丢失。

## 伊依独立长期记忆

Memo-N 另有一套与七张世界表完全分离的“伊依长期记忆库”。它负责记忆工程，不负责定义伊依的人格、文风、口癖或具体剧情表现；这些仍由当前预设和正常上下文决定。

- 存储在独立全局用户设置中，不写入当前聊天七表。
- 只有当前单人角色明确为“伊依”时才启用这套长期记忆；其他角色聊天即使正文提到“伊依”也不会读写她的独立记忆。
- 新游戏、换聊天或清空世界表不会自动清空伊依长期记忆。
- 每轮只召回少量与当前话题相关的长期记忆，不会全量塞入上下文。
- 自动写回复使用正文同一次模型请求，不额外增加 API 调用。
- Swipe、Regenerate、删除 Swipe、删除消息和编辑消息都使用独立事务回滚，避免不存在的分支留下“幽灵记忆”。
- 独立记录 API、表格整理等记录专用请求不会触发伊依记忆写回。
- 中转站普通一次 API 下，必须先闭合前置 `<tableEdit>`，然后输出正常正文；`<yiyiMemory>` 属于正常正文部分并保持在正文末尾，不能出现在前置 `<tableEdit>` 之前。

## 主要特性

- 正常模式只调用一次 API，不会因记录失败自动补发。
- DeepSeek / 中转站由用户手动选择，不再自动识别 Provider。
- 所有 API 记录入口都服从同一个「记录接口」设置。
- 普通/独立模式只有一个“填表行为发生在”选择器，不再存在重复模式开关。
- 表格操作只允许 `insertRow`、`updateRow`、`deleteRow` 或 `NO_CHANGE`。
- 一轮变更全部成功才保存，任一步失败都会完整回滚。
- 表格失败不删除正常正文，也不会猜测修复非法操作。
- 空表只能插入；更新和删除必须引用真实存在的行。
- 数字 `0` 会按原值保存。
- 每个聊天和 Swipe 使用各自的世界表格快照。
- 保留表格编辑、导入导出、整理、排序、行移动和表格目录移动等功能。
- 设置、API 私密数据、模板、聊天表格与 Swipe 数据均使用 Memo-N 独立存储键。

## 安装

插件目录必须命名为：

```text
SillyTavern/public/scripts/extensions/third-party/Memo-N
```

Memo-N 不是原 Memo 的覆盖升级包。安装 Memo-N 不会读取、迁移、删除或覆盖原 Memo 数据。

如果原 Memo 仍然安装，建议在 SillyTavern 扩展管理中只启用其中一个记录插件，避免两套插件同时向同一次模型请求注入各自的记录协议。即使同时存在，两者的持久化数据也彼此独立。

当前版本：`0.1.0-memon.75`。
